# Neptun Local — кастомная интеграция для Home Assistant

[![GitHub Release](https://img.shields.io/github/v/release/TSergeymsk/home-assistant-neptun-prowifi?style=flat-square)](https://github.com/TSergeymsk/home-assistant-neptun-prowifi/releases)

[![Home Assistant](https://img.shields.io/badge/Home%20Assistant-2026.10.5%2B-blue)](https://www.home-assistant.io/)

**Neptun Local** — локальная интеграция для системы защиты от протечек **Neptun ProW+**, построенная на базе логики проекта [neptun2mqtt](https://github.com/ptvoinfo/neptun2mqtt). Интеграция работает напрямую с контроллером по локальной сети — **без облака и без MQTT-посредника** — и предоставляет в Home Assistant все доступные состояния и элементы управления.

> **Важно:** интеграция использует **периодический опрос (polling)** контроллера. Активные push-события со стороны Нептуна в текущей версии протокола не поддерживаются.

## ✨ Возможности

- **Прямое локальное подключение** к контроллеру Neptun ProW+ по TCP (порт `6350`).
- ⚙️ **Гибкая настройка через UI** — все параметры подключения и логики работы задаются как при первичной настройке, так и в Options Flow (кроме IP-адреса).
- **Полный набор сенсоров** — общий статус, состояние клапана, количество беспроводных датчиков и реле, значения счётчиков, уровень сигнала и заряд батарей датчиков.
- **Бинарные сенсоры** — общая тревога (`ALARM`) и протечки по каждой линии (проводной и беспроводной).
- **Управление клапаном** — открытие/закрытие главного клапана через платформу `valve`.
- **Управление режимом очистки** — включение/выключение через платформу `switch`.
- **Автоматическая перезагрузка** при изменении параметров через Options Flow.

---

## Требования

- Home Assistant **2026.10.5** или новее.
- Контроллер **Neptun ProW+** с прошивкой, поддерживающей локальный TCP-протокол (порт `6350`).
- Контроллер и Home Assistant должны находиться в одной локальной сети (или быть связаны маршрутизацией без NAT для порта `6350`).
- Свободный статический IP-адрес для контроллера (рекомендуется).

## Установка

### Вариант 1: Вручную (HACS не требуется)

1. Скачайте или склонируйте репозиторий.
2. Скопируйте папку `custom_components/neptune_local` в директорию `config/custom_components/` вашего Home Assistant:

   ```
   /
   └── custom_components/
       └── neptune_local/
           ├── __init__.py
           ├── manifest.json
           ├── const.py
           ├── config_flow.py
           ├── coordinator.py
           ├── entity.py
           ├── sensor.py
           ├── binary_sensor.py
           ├── valve.py
           ├── switch.py
           ├── strings.json
           └── translations/
               └── en.json
   ```

3. Перезапустите Home Assistant.

### Вариант 2: Через HACS (как custom repository)

1. В HACS → **Integrations** → ⋮ → **Custom repositories**.
2. Добавьте URL вашего репозитория, категория — **Integration**.
3. Найдите **Neptun Local** в списке и установите.
4. Перезапустите Home Assistant.

## ⚙️ Настройка

### Первичная настройка

1. Перейдите в **Настройки → Устройства и службы → Добавить интеграцию**.
2. Найдите **Neptun Local**.
3. Заполните форму:

   | Параметр | Описание | По умолчанию |
   | :--- | :--- | :--- |
   | **IP address of the Neptun controller** (обязательно) | Локальный IP-адрес контроллера | — |
   | **Polling interval (seconds)** | Интервал опроса контроллера в секундах | `120` |
   | **Enable debug logging** | Включить подробное логирование для отладки | `False` |
   | **Retry attempts** | Количество повторных попыток при ошибке связи за один цикл | `2` |
   | **Retry delay (seconds)** | Задержка между повторными попытками в секундах | `8` |
   | **Max consecutive failures** | После скольких последовательных неудачных циклов интеграция перестаёт пытаться подключиться | `3` |

4. Нажмите **Отправить**. Интеграция создаст устройство **Neptun ProW+** и все сущности.

> Порт `6350` задан в коде как константа (`DEFAULT_PORT`) и в форме не запрашивается.

### Изменение параметров

1. **Настройки → Устройства и службы → Neptun Local → Настроить**.
2. Можно изменить **все параметры, кроме IP-адреса** (интервал опроса, отладку, повторы и т. д.).
3. Сохраните — интеграция автоматически перезагрузится с новыми параметрами.

> **Совет:** интервал опроса `120` секунд соответствует значению по умолчанию в оригинальном `neptun2mqtt`. Уменьшение интервала повышает отзывчивость, но увеличивает нагрузку на контроллер и сеть. Не рекомендуется ставить значение ниже `30` секунд.

## Сущности

После успешной настройки в Home Assistant появится устройство **Neptun ProW+** со следующими сущностями.

### Sensor

| Сущность | Описание | Значения |
| :--- | :--- | :--- |
| `sensor.neptun_prow_status` | Общий статус системы | `NORMAL`, `ALARM`, `MAIN BATTERY`, `SENSOR BATTERY`, `SENSOR OFFLINE` (комбинации через запятую) |
| `sensor.neptun_prow_valve_state` | Состояние главного клапана | `open` / `closed` |
| `sensor.neptun_prow_wireless_sensor_count` | Количество беспроводных датчиков | целое число |
| `sensor.neptun_prow_relay_count` | Количество реле | целое число |
| `sensor._value` | Показание счётчика (для проводных линий-счётчиков) | целое число |
| `sensor._signal` | Уровень сигнала беспроводного датчика | дБ |
| `sensor._battery` | Заряд батареи беспроводного датчика | % |

### Binary Sensor

| Сущность | Описание | Класс |
| :--- | :--- | :--- |
| `binary_sensor.neptun_prow_alarm` | Общая тревога (бит `ALARM` в статусе) | `problem` |
| `binary_sensor._leak` | Протечка по конкретной линии | `moisture` |

### Valve

| Сущность | Описание | Поддерживаемые функции |
| :--- | :--- | :--- |
| `valve.neptun_prow_main_valve` | Главный клапан | `open`, `close` |

### Switch

| Сущность | Описание |
| :--- | :--- |
| `switch.neptun_prow_cleaning_mode` | Режим очистки (отключение реакции на протечки) |

## Принцип работы

Интеграция реализует **периодический опрос** контроллера с заданным интервалом. Каждый цикл опроса состоит из последовательных запросов:

1. **`PACKET_SYSTEM_STATE` (0x52)** — общее состояние системы: положение клапана, флаги режимов, состояние проводных линий.
2. **`PACKET_BACK_STATE` (0x42)** — фоновый статус: битовая маска тревог (`ALARM`, `MAIN BATTERY`, `SENSOR BATTERY`, `SENSOR OFFLINE`).
3. **`PACKET_SENSOR_STATE` (0x53)** — состояние беспроводных датчиков: сигнал, линия, батарея, состояние.
4. **`PACKET_COUNTER_STATE` (0x43)** — показания счётчиков на проводных линиях.

Ответы парсятся в единую структуру данных, которая затем публикуется в сущности Home Assistant через `DataUpdateCoordinator`.

Для управления используется пакет **`PACKET_SET_SYSTEM_STATE` (0x57)**, содержащий новые флаги клапана и режима очистки.

> ⚠️ **Ограничение протокола:** контроллер Neptun не инициирует асинхронные уведомления. Все изменения становятся видны в Home Assistant только после следующего цикла опроса. Задержка обнаружения протечки не превышает настроенного интервала опроса.

## 🛠 Устранение неполадок

### Интеграция не подключается

- Убедитесь, что IP-адрес контроллера указан верно и он доступен из сети Home Assistant:
  ```bash
  ping <IP-адрес>
  ```
- Проверьте, что порт `6350` открыт и не блокируется файрволом:
  ```bash
  nc -zv <IP-адрес> 6350
  ```
- Убедитесь, что контроллер не занят другим клиентом (например, оригинальным `neptun2mqtt` или мобильным приложением). Некоторые прошивки допускают только одно активное TCP-подключение.

### Сущности показывают `unavailable`

- Проверьте лог Home Assistant на наличие ошибок `Error communicating with Neptun`.
- Включите **Enable debug logging** в настройках интеграции для получения подробных логов.
- Увеличьте интервал опроса или количество повторных попыток (`Retry attempts`).
- Убедитесь, что контроллер не перезагружается и стабильно питается.

### Не создаются сущности линий (счётчиков / беспроводных датчиков)

- Сущности линий создаются только для тех линий, которые были обнаружены в первом успешном цикле опроса. Если линии были добавлены в контроллер позже — перезагрузите интеграцию (**Настройки → Устройства и службы → Neptun Local → ⋮ → Перезагрузить**).

### Команды управления не применяются

- Проверьте, что контроллер не находится в режиме блокировки локального управления.
- Убедитесь, что между отправкой команды и следующим циклом опроса прошло достаточно времени для применения изменений на устройстве.

## Совместимость и ограничения

- **Поддерживаемые модели:** Neptun ProW+ (протокол, используемый в `neptun2mqtt`). Другие модели Neptun (например, Neptun Smart, Neptun Base) могут использовать иной протокол и **не поддерживаются**.
- **Только локальная работа:** интеграция не использует облако Neptun и не требует интернета.
- **Только polling:** активные уведомления со стороны контроллера не поддерживаются протоколом.
- **Один экземпляр интеграции на контроллер:** уникальность обеспечивается по IP-адресу; повторная настройка того же IP будет отклонена.

## Структура проекта

```text
custom_components/neptune_local/
├── __init__.py            # Точка входа интеграции
├── manifest.json          # Метаданные интеграции
├── const.py               # Константы, ключи конфигурации и значения по умолчанию
├── config_flow.py         # Первичная настройка и Options Flow
├── coordinator.py         # DataUpdateCoordinator + TCP-клиент протокола
├── entity.py              # Базовый класс сущностей
├── sensor.py              # Сенсоры (статус, клапан, линии, батареи, сигнал)
├── binary_sensor.py       # Бинарные сенсоры (тревога, протечки)
├── valve.py               # Главный клапан
├── switch.py              # Режим очистки
├── strings.json           # Строки UI (английский по умолчанию)
└── translations/
    └── en.json            # Переводы
```
